# llama.cpp Colab Builder

Сборка **llama.cpp** (последний семантический релиз `vX.Y.Z`) с наложением **Pull Request** под разные CUDA-архитектуры в Google Colab и публикация результата на **Google Drive**.

## Что делает

1. Устанавливает зависимости (`cmake`, `ninja`, `build-essential`, `libopenblas`, ...).
2. Клонирует `ggml-org/llama.cpp`, делает checkout последнего тега вида `vX.Y.Z`.
3. Накладывает PR №`<PR_NUMBER>` (по умолчанию `27537`) одним способом:
   `git apply --3way` на `pull/N.diff` (строгая «трёхточечная» разница — только изменения PR; при дрейфе контекста — 3-way merge по блобам репозитория).
4. Собирает цели `llama-cli`, `llama-server`, `llama-bench`, `llama-perplexity`, `llama-tokenize` для архитектур:

   | Архитектура | CUDA |
   |---|---|
   | `cpu` | — (OpenBLAS) |
   | `gpu_all` | 75;80;89 (одна универсальная сборка на T4 sm_75, A100 sm_80, L4 sm_89) |

5. Собирает **три варианта** по `GGML_NATIVE` / типу линковки:
   - `universal` (`-DGGML_NATIVE=OFF`) — переносимая сборка: CPU SSE4.2/AVX/AVX2/FMA/F16C/BMI2 (без AVX-512), CUDA во все арки. Работает на всех рантаймах Colab (в т.ч. EPYC без avx512f). Разделяемые `.so`.
   - `native` (`-DGGML_NATIVE=ON`) — оптимизация строго под машину сборки (в т.ч. CUDA-арка `native`). Разделяемые `.so`.
   - `native-static` (`-DGGML_NATIVE=ON -DBUILD_SHARED_LIBS=OFF`) — статически слинкованные исполняемые файлы (llama/ggml вкомпонованы в бинарники; системные glibc/OpenBLAS остаются динамическими). Официальный способ из `docs/build.md`: «For static builds, add `-DBUILD_SHARED_LIBS=OFF`».
6. Запускает smoke-тесты (`ldd`, `--version`).
7. Публикует на Drive: распакованные папки и архивы `tar.gz` на каждый вариант/архитектуру + общий манифест.

> Вывод по контрольным суммам прошлых сборок (`llama.cpp_v0.4.1_pr27537`, анализ 15.09.2026): между сборками t4/l4/a100/gpu_all побайтово идентично **всё**, кроме `libggml-cuda.so.0.24.0` — раздельные GPU-сборки не нужны, достаточно одной универсальной (`75;80;89`). Поэтому по умолчанию собирается `cpu` + `gpu_all`.

## Улучшения относительно исходного скрипта

- **Инкрементальная сборка.** Одно build-дерево переиспользуется между архитектурами и вариантами; при смене `CMAKE_CUDA_ARCHITECTURES`/`GGML_NATIVE` ninja пересобирает только затронутую часть.
- **Актуальные ключи CMake.** CUDA-арки задаются через официальный `-DCMAKE_CUDA_ARCHITECTURES` (устаревший `GGML_CUDA_ARCHITECTURES` в v0.4.1 не используется); OpenBLAS — через `-DGGML_BLAS=ON -DGGML_BLAS_VENDOR=OpenBLAS`.
- **Без deadlock.** Вывод команд потоково пишется в лог-файл (вместо `capture_output=True`, рискованного на больших объёмах вывода).
- **Атомарная публикация.** Сборка идёт локально в `/content/out`; на Drive результат копируется во временную папку `.new` и заменяет старые артефакты только после успешной сборки и smoke-теста.
- **Без 0-байтных симлинков.** Файлы копируются с разыменованием ссылок (`cp -L`), потому на Drive не попадают пустые `.so`-ссылки.
- **Манифест.** `manifest.json` + `README.txt` с релизом, коммитом, методом наложения PR, флагами, датами, размером и SHA-256 всех артефактов.
- **Надёжность.** Ретраи сетевых операций с экспоненциальной задержкой, проверка свободного места до старта.

```

├── universal/                # GGML_NATIVE=OFF (переносимая сборка)
│   ├── cpu/                  # бинарники + .so
│   ├── cpu.tar.gz
│   ├── gpu_all/              # 75;80;89
│   └── gpu_all.tar.gz
├── native/                   # GGML_NATIVE=ON (под машину сборки)
│   ├── cpu/
│   ├── cpu.tar.gz
│   ├── gpu_all/
│   └── gpu_all.tar.gz
├── native-static/            # GGML_NATIVE=ON + BUILD_SHARED_LIBS=OFF (статические исполняемые)
│   ├── cpu/                  # только бинарники (без .so)
│   ├── cpu.tar.gz
│   ├── gpu_all/
│   └── gpu_all.tar.gz
├── manifest.json
└── README.txt
```

## Как использовать

1. Откройте `llama_cpp_colab_builder.ipynb` в **Google Colab** (Runtime → Change runtime type → **T4 GPU**).
2. Настройте `PR_NUMBER`, `NATIVE_VARIANTS`, `ARCHS` / `BUILD_TARGETS` в первой кодовой ячейке.
3. **Runtime → Run all** и подтвердите монтирование Google Drive.
4. Дождитесь «✅ Все операции завершены» и дождитесь досинхронизации Drive.

> Если в сессии нет GPU — будет собрана только `cpu`-версия (в обоих вариантах `GGML_NATIVE`).

## Справочник окружений

`environments.md` — эталонные характеристики 4 рантаймов Colab (no-GPU, T4, L4, A100): для оценки переносимости сборок.

## Ограничения

- Рантайм Colab предоставляет одну GPU; сборка `gpu_all` — кросс-компиляция под целевые архитектуры и проверяется только smoke-тестами (filenames, версии), не прогоном на реальном железе.
- Известная область риска исходной версии (0-байтные `.so`-симлинки на Drive) устранена за счёт `cp -L` и архивов `tar.gz`.
- Google Drive синхронизируется в фоне: перед закрытием сессии убедитесь, что загрузка завершена.
